# План разработки и передача

## Состояние передачи

Архитектурный комплект подготовлен. Приложение, расширение, корпус, профили и результаты экспериментов ещё не созданы. Следующий исполнитель начинает с этапа A; описание поздних этапов не разрешает считать их проверки уже пройденными.

## Этапы

| Этап | Работа | Результат и условие выхода |
|---|---|---|
| A. Сквозной пилот | По 3 видео каждого автора, 3 партии игрока, ручная разметка, движок, сравнение A/B/C | Отчёт о реализуемости и пользе; известные ошибки источников/синхронизации; стоимость пилота |
| B. Основание приложения | БД и миграции, MediaStore, jobs/outbox, провайдерные адаптеры, авторизация, минимальный импорт и просмотр | Контрактные проверки; повтор задач без дублей; сохранение версий и расходов |
| C. Запись и синхронизация | Расширение, восстановление загрузки, сверка PGN, ASR, редактор привязки | S01/S02 проходят на реальных партиях; проверены reconnect и потеря микрофона |
| D. Корпус и профиль | Каталог, извлечение, редактор эпизодов, принципы и публикация, гибридный поиск | Проверенная база 10–20 видео на автора и воспроизводимые версии; holdout изолирован |
| E. Разбор и диалог | ThoughtClaim, проверка кандидатов, разговор и аналитическая доска, голосовой ввод | S03 проходит; ответы привязаны к правильной позиции; не публикуются неверные линии |
| F. Приёмка и эксплуатация | Итоговый тест, выбор моделей, квоты, backups, восстановление, наблюдаемость | Все обязательные пороги пройдены либо явно зафиксирован непрошедший gate; инструкция установки |

Этап A допускает временный ручной процесс вместо готового UI. Он не требует разработки полного конвейера видео. B может начаться после проверки доступности входов A; масштабирование D и финальный продуктовый gate зависят от доказанной пользы профиля. C и подготовка проверенного корпуса D независимы после контрактов B.

## Задачи первого этапа

1. Зарегистрировать manifest пилотного корпуса: канал, URL, автор, доступность, train/holdout group, причина выбора.
2. Проверить два способа доступа: поддерживаемый video API и доступные файлы. Отметить реальные ограничения времени/кадров/квот.
3. Записать три собственные партии с микрофоном и экраном; выгрузить PGN с часами при наличии.
4. Подготовить проверенные эпизоды и мысли согласно evaluation; не приписывать автору невыраженные принципы.
5. Сравнить ASR на одних фрагментах, отдельно учитывая отрицания и шахматные поля.
6. Получить движковые факты; сгенерировать A/B/C без разработки сложного продукта.
7. Провести слепую оценку и измерить стоимость часа видео, эпизода, партии и ответа.
8. Зафиксировать pass/fail/inconclusive по H1–H5 и решение о следующем объёме корпуса.

## Проверки по подсистемам

| Подсистема | Необходимая проверка |
|---|---|
| PGN и правила | Начальный FEN, рокировка, en passant, превращение, чёрные, ошибочный SAN, неподдерживаемый вариант |
| Engine | Перспектива оценок, mate score, кандидаты вне MultiPV, история повторений, timeout |
| Capture | Закрытый popup, завершение service worker, refresh/reconnect, потеря сети/микрофона, сон, заполнение диска |
| Timeline | Речь на границе хода, мысли о прошлом ходе, несколько позиций, импорт без часов, отдельные часы устройств |
| Persistence | Повтор block/job, конфликт ревизий, crash после внешнего API, stale результаты, отмена |
| Video | Переворот, анимация, стрелки, две доски, новая партия, возврат и вариант, неизвестные права рокировки |
| Knowledge | Дубли train/holdout, чужая речь, противоречивые принципы, удаление источника, смена embeddings |
| Coach | Верный ход/неверная причина, верный план/просчёт, самокоррекция, отсутствие доказательств, слабое покрытие автора |
| Security | Токен capture не читает анализ, медиа закрыты авторизацией, URL не даёт доступ к внутренним адресам |
| Operations | Backup/restore, нехватка диска, rate limit, недоступный AI, зависший worker |

Автотесты должны проверять реальные контракты и наблюдаемое поведение. Изменение prompt оценивается регрессионным набором, а не только snapshot текста. Семантическая правильность объяснений требует ручной оценки; успешный unit test её не доказывает.

## Перед началом оплачиваемого пилота

Нужны конкретные видео и собственные записи, доступные API credentials и установленный предел расходов пакета. Это входы запуска, не причина менять архитектуру. Они пока не предоставлены и не созданы документацией.

Перед установкой нужны домен/HTTPS, секрет единственного аккаунта, каталоги постоянных данных и отдельное резервное хранилище. Если их нет, локальный пилот возможен, но эксплуатационная приёмка не выполнена.

## Definition of Done v1

- Пользователь записывает партию, импортирует PGN, исправляет привязку и обсуждает мысли с каждым из двух профилей.
- Каждая показанная линия проверена, а основные оценки мыслей имеют сохраняемые основания.
- Профили построены из проверенного корпуса, а результат holdout-проверки представлен честно.
- Выбор моделей подтверждён измерениями качества, стоимости и задержки.
- Повторная загрузка и перезапуск worker не создают дублей и не теряют подтверждённые данные.
- Изменения входов делают результаты явно устаревшими.
- Резервное восстановление проверено; чувствительные записи недоступны без авторизации.
- Документы и API соответствуют фактической реализации; все отклонения отражены в ADR.

## Риски, которые нельзя закрыть документацией

| Риск | Как проверить / уменьшить |
|---|---|
| Объяснения авторов мало различимы после контроля позиции | Слепое A/B/C и holdout; при отсутствии эффекта пересмотреть гипотезу профиля |
| Видео не даёт точной доски или недоступно провайдеру | Пилот доступа; PGN и ручная разметка; отклонять ненадёжные эпизоды |
| ASR искажает поля и отрицания | Терминологический тест и редактор; не нормализовать молча |
| DOM Lichess меняется | Изолированный адаптер, сверка PGN, явный incomplete, резервный импорт |
| Цена подготовки корпуса велика | Измерять стоимость verified-эпизода вместе с ручным трудом до масштабирования |
| LLM придумывает стратегическое объяснение | Проверка основания, ограничение утверждений, человеческая оценка |

Сроки разработки не назначаются без результатов пилота и состава исполнителей: риск извлечения видео доминирует над обычной реализацией CRUD и интерфейса.
